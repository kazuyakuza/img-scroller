## Tasks

### Task 1: Config file (existence + format decision)

- [ ] Introduce the application config file shipped alongside the binary; its contents/format are decided in this wave's architector step (contents must remain minimal and consistent with architecture.md's "On disk" note). No last-viewed persistence in the config (v1 constraint — session memory stays RAM-only).

### Task 2: Zip-style portable installer

- [ ] The user picks a destination folder; the package unzips the application binary AND the config file into that destination.
- [ ] Release builds for x64 AND x86: this wave consumes AND extends Wave 1's `scripts/build-windows.sh` — the x86 build is an extension of Wave 1's harness: the `i686-pc-windows-gnu` target plus the `gcc-mingw-w64-i686` toolchain addition to the tracked Dockerfile are added when the x86 target is realized; the exact extension mechanism/details are decided in this wave's architector step.
- [ ] The packaging mechanism (script vs program, archive tooling) is decided in this wave's architector step; the packaging consumes the produced x64/x86 artifacts (the produced `.exe` files) from the gitignored `dist/` locations.

### Task 3: Default-viewer registration helper/guidance

- [ ] The package includes a helper and/or guidance that helps the user register the app as the default image viewer (file associations) in Windows.
- [ ] The helper mechanism (script vs executable, exact mechanism) is decided in this wave's architector step — this wave file must not pre-select it.

### Task 4: Verification

- [ ] Unit tests for any pure packaging/config logic that exists — run via the dev-checks harness in the container per `docs/build.md` (`ALL CHECKS PASSED`: fmt/check/test/clippy; `alpine-vm` MCP; `vm_status` first; the command exit code is the authoritative success evidence).
- [ ] x64 AND x86 release builds via the extended Wave-1 build script inside the container (per Task 2) — each command exits `0` and leaves a non-empty artifact at the gitignored `dist/` locations; run through the `alpine-vm` MCP (call `vm_status` first; the command exit code is the authoritative success evidence).
- [ ] Manual UX check (OPERATOR-RUN on the real Windows 10/11 machine — agent-side GUI/runtime execution is impossible from the Linux container): run the installer flow on a clean destination dir → binary + config file present and app launches; default-viewer helper/guidance performs or guides correctly; packaged app navigations from Waves 1–6 still work from the installed location.
