# Wave 6 — Fast "Open with..." Menu

Wave 6 adds a fast "Open with..." menu entry that enumerates, at runtime, the programs the Windows system registered for the currently viewed file's type/extension and opens the current file with the chosen program — with no internal program database.

Requirements source:

- [.agent/project-info/brief.md](../../../.agent/project-info/brief.md) → `### Fast "Open with..." Menu`, `## Important Note for AI Agents`. Binding 2026-10-29 user corrections (planning-wave Addendum v2) applied in this file: none specific.

## Tasks

### Task 1: Runtime program enumeration

- [ ] Query the Windows system registration data at runtime for the programs associated with the currently displayed file's type/extension; build the menu list from that data only. NO internal/hardcoded program database.
- [ ] The enumeration mechanism (which system APIs / how) is decided in this wave's architector step — this wave file must not name implementation APIs or crates.

### Task 2: Open the current file with the selected program

- [ ] Selecting an entry opens the CURRENT displayed file with that program (hand-off to the system launcher mechanism per the architector decision).

### Task 3: Menu entry in the UI

- [ ] Add the "Open with..." menu entry/portal in the viewer UI; placement follows the propose-and-ask instruction (same UI-layout-pending-user-definition instruction as Waves 2–4: propose a concrete layout, then ASK the Planner/user for approval before finalizing).
- [ ] Behavior when NO programs are registered for the type is decided in this wave's architector step.

### Task 4: Verification

- [ ] Unit tests where pure logic exists (e.g., parsing/filtering of enumeration results represented in a testable seam) — run via the dev-checks harness in the container per `docs/build.md` (`ALL CHECKS PASSED`: fmt/check/test/clippy; `alpine-vm` MCP; `vm_status` first; the command exit code is the authoritative success evidence).
- [ ] Manual UX check (OPERATOR-RUN on the real Windows 10/11 machine — agent-side GUI/runtime execution is impossible from the Linux container): for a jpg/png file, the menu lists at least the system-associated programs; selecting one opens this exact file in that program; NOT dependent on any app-maintained list.

### Task 5: Documentation updates

- [ ] `README.md`, `tech.md`, `architecture.md`, `context.md`: record the enumeration mechanism chosen, constraints, remaining open items.
