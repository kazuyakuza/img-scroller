# Wave 3 — Vertical Scroll (Sibling Folders)

Wave 3 adds vertical navigation between sibling folders under the SAME parent folder, with a session-only RAM map of the last viewed image per visited folder, and up/down arrow keys plus on-screen up/down UI buttons.

## Tasks

### Task 1: Sibling-folder enumeration

- [ ] From the current image's folder, enumerate sibling folders under the SAME parent (e.g., from `parent\folder2\img1` → `parent\folder1`, `parent\folder3`). NEVER folders of `parent` (no grandparent jumping); NEVER recursive/deeper traversal.
- [ ] Sort folders alphanumeric (same collation as Wave 2 — one fixed order; the exact definition was decided in Wave 2's architector step and recorded in tech.md; reference that decision here).

### Task 2: Session last-viewed memory (deliverable of this wave)

- [ ] RAM-only map: current folder → last viewed image path (per folder visited this session). Update it whenever an image is displayed.
- [ ] Destroyed when the application closes; NO persistence to disk in v1 (no files written, no settings storage).

### Task 3: Target image priority rule — keyboard and buttons

- [ ] Up arrow key AND up UI button → previous sibling folder; Down arrow key AND down UI button → next sibling folder.
- [ ] Target image priority (binding correction): (a) if the target folder was already visited this session → its session last-viewed image; (b) otherwise → ALWAYS the target folder's FIRST image in alphanumeric order. NO same-filename attempt, NO other fallback.
- [ ] The newly shown image updates the session last-viewed map for the target folder.
- [ ] Behavior for a sibling folder containing no displayable image (skip it? disable? error?) is decided in this wave's architector step.
- [ ] Pan interaction: out of scope here — arrows navigate directly until Wave 5 implements pan-then-navigate.

### Task 4: Verification

- [ ] Unit tests: same-parent restriction (no grandparent/deeper jumps), sort order, target-image priority (visited → last-viewed; new folder → first image), last-viewed map set/get and per-session lifetime.
- [ ] `cargo build`, `cargo test`, `cargo run`; manual UX check: up/down keys and buttons move folders under the same parent; revisiting a folder this session reopens its last viewed image; closing and relaunching loses the memory.

### Task 5: Documentation updates

- [ ] `README.md`: vertical scroll + the corrected target rule (no same-filename rule — the version corrected per planning-wave Task 5). `tech.md`/`architecture.md`: record the session-memory component, the corrected navigation rule, remaining open items. `context.md`: closing update.
