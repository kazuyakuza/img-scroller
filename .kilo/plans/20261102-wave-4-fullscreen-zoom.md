## Global Pre-Analysis

- **Baseline app (0.3.0)**: egui/eframe `=0.37.0` (`default-features = false`, glow, Windows 10/11 via WIC). One window (`Images Scroller`, resizable, not maximized); center panel paints the decoded image fit-scaled/centered via `scaling::fitted_size` (per-frame recompute); ONE floating bottom-center pill (`src/app/floating_controls.rs`) with painted arrows + message line; `src/app/folder_navigation.rs` is the single `navigate` seam for all four directions; empty-folder browsing mode exists (`src/app/empty_folder_view.rs`).
- **Wave-4 additions (all session state — no persistence)**: fullscreen flag (default OFF at launch — window opens exactly as the user placed/sized it), zoom factor (manual zoom in/out), and fit mode (fit-all [current behavior], fit width, fit height).
- **Fullscreen mechanism candidate** (architector MUST verify against egui 0.37 current docs via context7): `ctx.send_viewport_command(egui::ViewportCommand::Fullscreen(bool))` toggles the native decorations on the glow backend; hiding ALL UI controls is code-level rendering gating (pill and any body-control not drawn while fullscreen ON; the image keeps its central area). Alternative mechanisms (e.g. native options change requiring app restart; `fullsize_content`) must be evaluated in 4.1a/4.1b before one is encoded.
- **Zoom mechanism candidate**: store `zoom_factor: f32` in `ImagesScrollerApp` (default `1.0`); display scales = fit-scale × zoom; UI buttons + keyboard; step size and min/max clamp proposed in 4.1a, encoded by 4.1b. Manual-zoom → fit-mode interaction and zoom-reset-on-open policy are architector decisions (encoded, never invented by coders).
- **Fit-mode mechanism candidate**: `FitMode` enum (`FitVisible` current default / `FitWidth` / `FitHeight`); `scaling.rs` gains width-only / height-only pure scale functions + unit tests (container-runnable); `app_display.rs` paints the size computed per current mode; window resize recomputes per frame as today.
- **UI-control placement**: the mandatory carried instruction (Waves 2–3) applies — `frontend-specialist` PROPOSES concrete placements, Planner presents them to the user with `question`, the user's pick is binding input to 4.1b. Applies to the fullscreen toggle, zoom in/out, and fit-mode controls.
